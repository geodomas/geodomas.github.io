# GEODOMAS AI Curriculum v1

## Training architecture

`Product ontology → GEODOMAS system logic → CALC vocabulary → geometry rules → connector/profile vocabulary → deterministic tools → project start → engineering boundaries → response protocol`

## What a trained public AI should be able to do

- distinguish GLAMPING / HOMES / GLAZED / ROOFS / MONOLIT / CRYSTAL / NATURAL HOME / INFINITY;
- explain how a project starts without pretending to be the engineer of record;
- read F(V), subdivision class/method, symmetry, partial sphere, base alignment and current connector/profile-system labels;
- use deterministic Model Spec / Geometry / Frame / CALC Mesh tools;
- explain what CALC data does and does not prove;
- refuse to promote mesh chords into a production cutting schedule;
- separate public orientation from structural, thermal, legal and commercial verification;
- route private/project-specific questions through controlled review.

## What it should not learn from public GitHub

- private BOM and manufacturing corrections;
- connector fabrication details beyond public vocabulary;
- supplier pricing, margins or internal price engines;
- client records and email;
- internal prompts, scoring and routing traces;
- unverified claims about loads, energy class, warranties or delivery time.

## Evaluation

Use `knowledge/curriculum/evaluation.jsonl` as a regression suite whenever the public ontology or CALC contract changes. An answer fails if it introduces a prohibited claim even if the geometry terminology is otherwise correct.
